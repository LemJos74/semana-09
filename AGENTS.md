# AGENTS.md

Angular 22 app (CLI 22.0.1, TypeScript ~6.0, Vitest 4, npm 11) generated by `ng new` with SSR. Single project `semana-09` rooted at the workspace root; source in `src/`, static assets in `public/`, build output in `dist/semana-09/`.

## Commands

- Dev server: `npm start` (`ng serve`) → http://localhost:4200, hot reload.
- Verify (run in this order): `npx ng build` → `npx ng test --watch=false`. That is the whole check: there is **no lint/ESLint config, no typecheck script, and no CI workflows**. `ng build` is the type check (tsc project refs + Angular compiler) and also enforces size budgets.
- Unit tests: `ng test` runs Vitest and **watch mode is on by default in a TTY** — always pass `--watch=false` for a one-shot run. Run a single test/suite: `ng test --watch=false --filter="<regex on suite/test name>"`; run one file: `ng test --watch=false --include src/app/app.spec.ts`. Defaults to jsdom in Node; no browser install needed.
- Production build: `ng build` (production is the default config). Budgets fail the build: initial 500kB warn / 1MB error, **per-component CSS 4kB warn / 8kB error** — oversized `*.css` in components is a real failure mode.
- Run the built SSR app: `npm run build` then `npm run serve:ssr:semana-09` → serves `dist/semana-09/server/server.mjs` on `PORT` or **4000** (not 4200).
- Prettier is configured (`.prettierrc`: 100 cols, single quotes, `angular` parser for `*.html`) but has no npm script, and the stock scaffold is **not** currently prettier-clean (`prettier --check .` flags 23 files). Format the files you touch with `npx prettier --write <paths>`; do not mass-format the repo.

## Architecture (SSR is on)

- `outputMode: "server"` in `angular.json`. Entrypoints: browser `src/main.ts`, server bootstrap `src/main.server.ts`, Express server `src/server.ts`.
- The Express layer is where any API/REST endpoints go (`src/server.ts` has a commented example) — they run only in the Node server, never in the browser.
- All routes prerender: `src/app/app.routes.server.ts` sets `RenderMode.Prerender` for `**`. New dynamic routes must be switched to `RenderMode.Server`/`Client` deliberately.
- Client hydration is enabled (`provideClientHydration()` in `src/app/app.config.ts`); server config merges it via `src/app/app.config.server.ts`.
- App routes: `src/app/app.routes.ts` (currently empty; root component renders `<router-outlet>`).

## Project structure (required)

- Layout is **component + service**: components live in `src/app/components/<name>/` (with `<name>.ts`, `<name>.html`, `<name>.css`) and their services in `src/app/services/<name>.ts`. Keep them paired by feature name.
- `src/app/interfaces/` is mandatory: all interfaces/type models go there, one per file, PascalCase names matching the file name.
- Component templates are always separate `.html` files referenced with `templateUrl` — never inline `template: \`...\`` strings.

## Conventions

- **Angular 22 file naming is not the classic one**: files are named after the element, class after the selector base. Root component is `src/app/app.ts` with `export class App`, `app.html`, `app.css` — not `app.component.ts`. `ng g component foo` produces `foo.ts`/`foo.html`/`foo.css` with class `Foo`, selector prefix `app`.
- Everything is standalone: no `NgModule`s; new dependencies go in the `imports: []` of `@Component`.
- Specs use Vitest **globals** (`vitest/globals` in `tsconfig.spec.json`) — `describe`/`it`/`expect` need no import. Follow the `TestBed.configureTestingModule({ imports: [...] }).compileComponents()` pattern in `src/app/app.spec.ts`.
- Component state uses signals (`signal(...)` in `src/app/app.ts`).
- `tsconfig.json` enables `noImplicitReturns`, `noPropertyAccessFromIndexSignature`, `noFallthroughCasesInSwitch` — dot access on index signatures is an error; use `obj['key']`.
- Style: 2-space indent, single quotes, final newline (`.editorconfig`); class-based selectors/components prefixed `app`.
